## 1. Datasets

| Dataset | Source | Official Split Used | Images |
|---------|--------|---------------------|--------|
| FER2013 | Kaggle (`fer2013.csv`) | `Usage == "PrivateTest"` for test; rest for train/val | ~35,887 |
| RAF-DB | `af-db.zip` | Files prefixed `test_` for test; `train_` for train/val | ~15,339 |
| AffectNet | Local directory (`AffectNet/`) | `Test/` subdirectory for test; `Train/` for train/val | ~30,626 |

### 1.1 Label Mapping

All datasets are mapped to a **unified 7-class** scheme:

| Class ID | Emotion |
|----------|---------|
| 0 | Anger |
| 1 | Disgust |
| 2 | Fear |
| 3 | Happy |
| 4 | Sad |
| 5 | Surprise |
| 6 | Neutral |

Samples with unknown or unmapped labels are **discarded** before any counting or balancing. This is why the class-distribution counts (Tables 2 and 3 in `dataset_stats_report.md`) are lower than the raw corpus sizes (Table 1).

### 1.2 Dataset Size Clarification

Three distinct counts exist and should **not** be confused:

1. **Raw corpus size** — total images in each dataset before any filtering (see Table 1 in `dataset_stats_report.md`)
2. **Class distribution before balancing** — after label mapping and unknown-label removal (Table 2)
3. **Class distribution after balancing** — after oversampling / undersampling (Table 3)

The report `dataset_stats_report.md` is auto-generated by `dataset_balancer.print_dataset_report()` at the start of every run.

## 2. Data Splits

| Split | Fraction | Purpose |
|-------|----------|---------|
| Training | 0.70 | Model parameter updates |
| Validation | 0.15 | Hyperparameter tuning and model selection |
| Test | 0.15 | Final metric reporting (never used during training) |

- Splits are drawn with **stratified random sampling** per class.
- Random seed is fixed **before** splitting (see §6).
- Split indices are saved to `split_indices.json` so exact splits can be restored (see `utils.load_split_indices()`).
- Validation and test sets are **completely disjoint**.
- For benchmark evaluation (`benchmark_eval.py`), the **official test splits** of each dataset are used instead of the 15% held-out slice.

## 3. Class Balancing

| Parameter | Value |
|-----------|-------|
| `balance_method` | `"both"` (oversample minority + undersample majority) |
| `min_samples_per_class` | 8,000 |
| `max_samples_per_class` | 8,000 |
| Target total (7 classes) | 56,000 balanced training samples |

- **Oversampling**: Repeated sampling with replacement for minority classes until `min_samples_per_class` is reached.
- **Undersampling**: Random sampling without replacement for majority classes down to `max_samples_per_class`.
- `use_class_sampler` is set to `false` when `balance_dataset = true` to avoid double-weighting.
- Balancing is applied to the **training split only**; validation and test splits remain unmodified.

## 5. Training Protocol — Two-Phase Progressive Fine-Tuning

### Phase 1: Warmup (Head-Only Training)

| Parameter | Value |
|-----------|-------|
| Epochs | 2 |
| Backbone | Frozen |
| Only trained | Classification head |
| Input size | 224 × 224 |
| Augmentation | Mild (resize + horizontal flip + normalize only) |
| LR scheduler | Linear warmup → cosine decay (full phase) |

**Purpose**: Stabilise the randomly initialised classification head before unlocking the backbone, preventing large gradient magnitudes from corrupting pre-trained features.

### Phase 2: Full Fine-Tuning

| Parameter | Value |
|-----------|-------|
| Epochs | 25 |
| Backbone | Fully unfrozen |
| Input size | 256 × 256 |
| Augmentation | Full pipeline (see §7) |
| Early stopping patience | 10 epochs |

## 6. Optimiser and Learning Rate Schedule

| Parameter | Value | Notes |
|-----------|-------|-------|
| Optimiser | AdamW | PyTorch `torch.optim.AdamW` |
| Base LR (`η`) | 3.0 × 10⁻⁵ | Applied to head during warmup |
| Head LR (fine-tune) | `η × r_ft = 9.0 × 10⁻⁶` | `r_ft = 0.3` |
| Backbone LR (fine-tune) | `η × r_ft × r_bb = 9.0 × 10⁻⁷` | `r_bb = 0.1` |
| Weight decay (`λ_wd`) | 0.05 | Applied uniformly |
| LR schedule | Linear warmup → cosine decay | See equation below |
| Warmup start factor | 0.01 | LR starts at `0.01 × base_lr` |
| Warmup length | 1 epoch of optimiser steps | Default |
| Minimum LR (`η_min`) | `0.01 × η` | Cosine decay floor |
| Gradient clipping (`max_grad_norm`) | 5.0 | L2 norm of all parameters |

### LR Schedule Formula

```
         ┌ η × (0.01 + 0.99 × t / T_warm)                    if t ≤ T_warm
η(t)  =  │
         └ η_min + (η - η_min) × (1 + cos(π × (t-T_warm) / (T_total-T_warm))) / 2   otherwise
```

where `T_warm` = warmup steps, `T_total` = total optimiser steps.

---

## 7. Gradient Accumulation and Effective Batch Size

| Parameter | Value |
|-----------|-------|
| Mini-batch size (`B`) | 32 |
| Gradient accumulation steps (`G`) | 2 |
| **Effective batch size** (`B_eff = B × G`) | **64** |

**Mechanism**: Gradients are computed for each mini-batch but the loss is normalised by dividing by `G` before `backward()`. The optimiser step is invoked only every `G` mini-batches. This is mathematically equivalent to a batch size of 64 on a single GPU without needing extra memory.

```python
loss = base_loss / grad_accum          # scale down before accumulating
scaler.scale(loss).backward()          # accumulate
if step % grad_accum == 0:
    scaler.step(optimizer)             # update every G steps
    optimizer.zero_grad()
```

This is implemented in `train_engine.py` and configured via `configs/kaggle_2gpu.yaml`.

## 8. Regularisation

| Technique | Value |
|-----------|-------|
| Label smoothing (`ε`) | 0.1 |
| Head dropout | 0.2 |
| Focal loss | Disabled (`use_focal_loss: false`) |
| Exponential Moving Average (EMA) | Enabled |
| EMA decay (`β`) | 0.9997 |

EMA shadow weights are used for validation and test evaluation. The backbone EMA is **disabled** during the warmup phase to prevent the randomly initialised head from corrupting shadow weights.

## 9. Data Augmentation

### Training Pipeline

| Augmentation | Parameters | Probability |
|-------------|-----------|-------------|
| Random horizontal flip | — | 0.5 |
| RandAugment | ops = 2, magnitude = 9 | Always (when enabled) |
| Random Erasing | — | p = 0.2 |
| MixUp | α = 0.4 | p = 0.5 per batch |
| CutMix | α = 1.0 | Disabled |
| **Novel: FourierAugment** | α_low = 0.8, α_mid = 1.2 | p = 0.4 |
| **Novel: ContrastiveNoiseAug** | — | p = 0.3 |
| **Novel: AugMixLite** | — | p = 0.4 |

All images are normalised using ImageNet statistics:  
`mean = [0.485, 0.456, 0.406]`, `std = [0.229, 0.224, 0.225]`

### Validation / Test Pipeline

Resize → Centre Crop → Normalise (no stochastic augmentations).  
Test-Time Augmentation (TTA): horizontal flip ensemble (`use_tta: true`), providing +0.5–1.5% accuracy.

## 11. Model Selection Criterion

The **best checkpoint** is selected as the model epoch with the **highest validation accuracy** during the fine-tuning phase.

- Saved as `{model_name}_best.pth` (weights only) and `{model_name}_best_full.pth` (weights + optimiser + scheduler state)
- Final test metrics are computed from this checkpoint, not from the last epoch
- Early stopping halts training when validation accuracy does not improve for 10 consecutive epochs

## 12. Evaluation

### 12.1 Unified Dataset Evaluation

Evaluated on the 15% held-out test split of the unified FER2013 + RAF-DB + AffectNet dataset.

> **Important**: This accuracy is **not directly comparable** to single-dataset SOTA results because the test distribution differs from any individual benchmark. See `benchmark_eval.py` for per-dataset standard-split results.

### 12.2 Per-Dataset Standard-Split Evaluation (`benchmark_eval.py`)

| Dataset | Official Test Split Definition |
|---------|-------------------------------|
| FER2013 | Rows where `Usage == "PrivateTest"` in `fer2013.csv` |
| RAF-DB | Image files whose filename starts with `test_` |
| AffectNet | Images inside the `Test/` subdirectory |

These splits are the **community-standard** held-out sets used in all published SOTA comparisons. Numbers from this evaluation are directly comparable to literature values.

### 12.3 Cross-Dataset Evaluation (`cross_dataset_eval.py`)

- Trains on one dataset, tests on the other two
- All 6 directional pairs (A→B, A→C, B→A, B→C, C→A, C→B)
- Per-pair confusion matrices saved as PNG
- Domain-shift diagnosis: identifies collapsed classes (per-class accuracy < 20%)
- KL divergence computed between dataset label distributions
- Markdown diagnostic report (`domain_shift_report.md`) auto-generated

### 12.4 Reported Metrics

| Metric | Description |
|--------|-------------|
| Accuracy | Overall top-1 classification accuracy |
| Macro F1 | Unweighted mean F1 across all 7 classes |
| Weighted F1 | F1 weighted by class support |
| AUC | Area under the ROC curve (one-vs-rest, macro) |

## 13. Baseline Comparison Protocol (`baseline_runner.py`)

Baselines (ResNet-18, ResNet-50, EfficientNet-B0) are trained using the **identical configuration** as the proposed ConvNeXt-V2 model:
- Same YAML config file
- Same dataset splits (via `split_indices.json`)
- Same augmentation policy
- Same optimiser, LR, weight decay, epochs
- Same benchmark evaluation on official test splits

Results are tagged `"Protocol": "Reproduced (identical YAML config + standard test splits)"` in the comparison table.

Literature SOTA values (ResEmoteNet, POSTER V2, SSFER, MSAFNet) are tagged `"Protocol": "Literature-reported"` and use each paper's own training/evaluation setup. **These are not directly comparable** to reproduced numbers.

## 14. Ablation Study Protocol (`ablation_study.py`)

| Parameter | Value |
|-----------|-------|
| Seeds | `[42, 123, 456]` (3 independent runs) |
| Significance test | Welch two-sample t-test (pairwise) |
| Output | `ablation_results.json`, `ablation_significance_tests.csv` |

**Explainability note**: The "explainability-aware training" entry in the ablation table refers to the inclusion of Grad-CAM and landmark heatmap generation **after** training. Grad-CAM is a **post-hoc visualisation tool** — it does not contribute any loss term, gradient signal, or parameter update during training. It is an evaluation feature, not a training objective.
